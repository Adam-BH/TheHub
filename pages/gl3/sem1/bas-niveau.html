Chapitre IProcesseur · mémoire · E/S

Relier un processeur à des mémoires et des périphériques, ligne par ligne.

§1.1Les 3 bus

BusLignesRôle
AdresseN lignes A0…A(N−1)capacité = 2N octets (0 … 2N−1), 1 adresse par octet
DonnéesM lignestaille du mot (8/16/32) : M/8 octets par cycle
Contrôle/RD, /WR, Byte Selectlecture / écriture (actifs à 0), nb d'octets

§1.2La puce mémoire

Taille = 2n × m bits = 2n × (m/8) octets
n = lignes d'adresse (profondeur : nombre de lignes), m = largeur d'une ligne.
/CE = 0 : connectée · /CE = 1 : haute impédance. Une seule puce active à la fois sur un même fil de données, sinon court-circuit.

§1.3La règle des bits d'adresse

Le processeur compte des octets, la mémoire compte des lignes. On découpe l'adresse en partant du bas :

bits bas → Byte Select·n bits suivants → broches A de la mémoire·bits hauts restants → /CE

Nb de bits Byte Select = log₂(M/8) : 0 (M=8), 1 = A0 (M=16), 2 = A1A0 (M=32).

Même largeur (M = m), N = 12nCâblageByte Select
M = m = 812A11…A0 → A11…A0—
M = m = 1611A11…A1 → A10…A0A0
M = m = 3210A11…A2 → A9…A0A1A0

§1.4Mémoire trop étroite (m < M) : en parallèle

M/m puces côte à côte, mêmes lignes d'adresse, même /CE (elles travaillent ensemble sur des fils différents). Le bus de données est découpé : Mem0 ← D7–D0, Mem1 ← D15–D8, Mem2 ← D23–D16, Mem3 ← D31–D24. Ici A1A0 = « quelle puce ».
Ex. N=12, M=32, 4 × 8 bits (n=10) : A11…A2 → A9…A0 de chaque puce. Octet 6 = 0…01|10 → ligne 1, Mem2.

§1.5Mémoire trop petite : décodage par /CE

Les puces partagent les mêmes fils → chacune son /CE, piloté par les bits hauts (chaque puce = un bloc d'adresses contigu).
Ex. N=12, M=m=32, n=9 (2 Ko) : A10…A2 → A8…A0, /CE0 = A11 (0–2047), /CE1 = ¬A11 (2048–4095). Adresse 2050 = 1|000000000|10 → Mem1, ligne 0, octet 2.
2 bits libres (A11 A10) → 4 puces : /CE0 actif pour 00, … , /CE3 pour 11.
Les deux à la fois (banques) : puces par banque = M/m · banques = 2N / taille d'une banque. Ex. N=12, M=32, puces 512×8 : 4 par banque (2 Ko), 2 banques (A11) → 8 puces.

Variable 32 bits → adresse multiple de 4 (alignement). Lecture : /CE=0, /RD=0, adresse → la mémoire pilote le bus de données. Écriture : /CE=0, /WR=0, adresse + donnée → le processeur pilote.

§1.7Interface de périphérique (8255)

Câblée comme une mémoire ; pour le CPU c'est quelques registres à adresses fixes. Certains bits sont reliés aux broches : bit 1 ↔ +V, bit 0 ↔ 0 V. Écrire = bits → broches (LED, afficheur). Lire = broches → bits (boutons) : masquer les bits non câblés (aléatoires).
Ex. 7 segments PC7=a…PC1=g : « 3 » = a b c d g = 0xF2.

§1.8Masquage logique

Écrire *Reg = 0x80 efface aussi les autres bits. On fait donc effacer puis écrire : &= ~(masque << i) puis |= valeur << i. Chaque opération = lecture + calcul + écriture (3 instructions). Les recettes complètes sont dans Code → Masquage et au §2.5.

§2.2Un port = 16 broches

GPIOA…GPIOG, 16 pins chacun (PC9 = port C, pin 9). Dans IDR, ODR, BSRR, BRR : bit i = pin i (bits 0–15). Dans CRL/CRH : 4 bits par pin.

§2.3CRL / CRH : le quartet CNF | MODE

pin p → CRL si p < 8, sinon CRH · décalage = 4 × (p mod 8)
Quartet = CNF1 CNF0 (type) MODE1 MODE0 (00 = entrée ; 01/10/11 = sortie 10/2/50 MHz).
ConfigurationQuartetHex
Entrée analogique00000x0
Entrée flottante (reset)01000x4
Entrée pull-up / pull-down10000x8
Sortie push-pull 10 / 2 / 50 MHz0001 / 0010 / 00110x1 / 0x2 / 0x3
Sortie open-drain 2 MHz01100x6
Fonction alternative push-pull 50 MHz10110xB
  • Le mode décide : en sortie la broche suit ODR ; en entrée IDR recopie la broche (IDR est en lecture seule).
  • Pull-up/down : valeur par défaut d'une entrée non pilotée. Bouton vers GND → pull-up ; bouton vers 3,3 V → pull-down. Sur F1 (hors diapos) : 1000 + bit ODR = 1 → pull-up, 0 → pull-down.
  • Push-pull pilote 3,3 V et 0 V ; open-drain ne tire qu'à 0 V (résistance externe pour le 1). Seul le quartet change dans le code.

Chapitre IVCommunication série en polling (F4)


Même HAL, mais pour parler à d'autres puces : handle, attente sur bits d'état, timeout.



§4.1Le handle


PPP_HandleTypeDef = Instance (registres, ex. USART2) + Init (config) + état (buffers, compteurs). On passe toujours &handle. Les fonctions renvoient HAL_OK / HAL_ERROR / HAL_BUSY / HAL_TIMEOUT.



§4.2UART


    

  • 2 fils croisés (TX → RX) + GND, asynchrone : pas d'horloge, les deux côtés fixent le baud rate (9600 bit/s ≈ 1 ms par octet).
    • 

  • Trame : ligne au repos à 1 · start 0 · 8 ou 9 bits de données (LSB d'abord) · parité optionnelle · stop 1 (1 ou 2).
    • 

  • Registres : DR (données), SR : TXE bit 7 = prêt à émettre, RXNE bit 5 = octet reçu ; BRR (vitesse) ; CR1 (UE, TE, RE, M, PCE).
    • 

  • Broches en fonction alternative : AF_PP, PULLUP, GPIO_AF7_USART2. PA2/PA3 = USART2 (AF7), PA9/PA10 = USART1 (AF7), PA11/PA12 = USART6 (AF8).
    • 



Pourquoi attendre ? Écrire DR en boucle va trop vite (MHz) pour la ligne (kHz) : les octets s'écrasent. Polling = while (!(SR & 0x80)); avant chaque octet, mais c'est bloquant. HAL_UART_Transmit fait la même attente avec un timeout.


CubeMX génère MX_GPIO_Init() et MX_USART2_UART_Init() ; on écrit seulement la logique dans main.c.



§4.3I2C


    

  • 2 fils partagés : SCL (horloge, du maître) et SDA (données, half-duplex). Plusieurs esclaves, chacun une adresse 7 bits (128) ou 10 bits.
    • 

  • Start : SDA descend pendant SCL = 1 · Stop : SDA monte pendant SCL = 1 · ACK après chaque octet (géré par le matériel).
    • 

  • Écrire un registre : S · adr+W · A · reg · A · data… · P. Lire : écrire reg, puis restart · adr+R · data… · P.
    • 

  • La HAL veut l'adresse décalée : 0x1D << 1 = 0x3A (bit 0 = R/W).
    • 



LIS3DSH : adresse 0x1D → 0x3A. Activer : CTRL_REG4 (0x20) = 0x77 (ODR 0111, BDU 0, Z Y X = 111). Lire Z : 2 octets à 0x2C–0x2D.


Diapos 17/19 : &huart2, pas huart2. sizeof("Hello") = 6 (le '\0'). Diapo 16 : indices 0…4. SPI annoncé dans le titre mais non traité.








Chapitre VInterruptions (diapos 1–52)


Le périphérique prévient le processeur au lieu d'être interrogé en boucle.



§5.1Polling ou interruptions


Polling : tests répétés, CPU et énergie gaspillés, événements ratés. Interruption : chaque périphérique a une ligne IRQ ; main n'est interrompu que s'il se passe quelque chose.



§5.2Les acteurs


    

  • ISR (handler) : fonction C qui traite l'événement, en Flash avec main.
    • 

  • Table des vecteurs : au début de la Flash, tableau des adresses des ISR, 4 octets chacune → @ISR n à base + 4 × n.
    • 

  • Contrôleur : registres pending (en attente), mask/enable (autorisée), active (en cours), priorité.
    • 

  • INT (contrôleur → CPU) : « ça sonne ». /INTA (CPU → contrôleur, actif à 0) : « je décroche ».
    • 




§5.3La chaîne et les 6 étapes


événement→flag = 1→IT enable périph ?→IRQ → pending = 1→enable NVIC + priorité ?→INT




#Étape


1Événement → flag → IRQ → pending ; non masquée → INT = 1


2Le CPU termine l'instruction X, répond /INTA = 0


3PUSH : sauve @X+1 et les registres dans la pile ; lit @ISR dans la table (4 × n)


4Exécute l'ISR ; INT retombe ; pending effacé automatiquement


5POP : restaure le contexte


6Reprend main à X+1




Effacer le flag dans l'ISR, sinon pending revient et l'ISR tourne en boucle (sauf SysTick, effacé seul).


Interruption masquée : enable NVIC = 0 → flag et pending passent à 1, INT reste à 0, rien ne se passe ; dès qu'on met enable à 1, elle se déclenche (en retard). IT enable du périphérique = 0 → l'IRQ ne monte jamais, pas d'interruption du tout.



§5.4Plusieurs interruptions




Nouvelle IRQ pendant une ISR, priorité…Résultat


plus basse ou égaleChaînage : elle attend (pending) puis passe après


plus hauteImbrication : elle interrompt l'ISR en cours (2e PUSH), qui reprend ensuite




Interruption globale : tous les événements d'un périphérique en OU sur une seule IRQ → l'ISR teste les flags pour savoir lequel.

§5.8Priorités


    

  • 4 bits, plus petit = plus prioritaire, découpés en préemption | sous-priorité selon PRIGROUP (AIRCR, clé 0x05FA dans les bits 31–16).

    •

HAL_GPIO_Init maison (F1)

void HAL_GPIO_Init(GPIO_TypeDef *GPIOx, GPIO_InitTypeDef *S){
  uint8_t  cfg = (S->Mode << 2) | S->Speed;
  uint32_t mL=0, cL=0, mH=0, cH=0;
  for (int p = 0; p < 16; p++)
    if (S->Pin & (1u << p)) {
      if (p <= 7) { mL |= 0xFu<<4*p;     cL |= cfg<<4*p; }
      else        { mH |= 0xFu<<4*(p-8); cH |= cfg<<4*(p-8); }
    }
  GPIOx->CRL &= ~mL;  GPIOx->CRL |= cL;   // 8 accès au total
  GPIOx->CRH &= ~mH;  GPIOx->CRH |= cH;
}
