Avant de programmer un microcontrôleur, il faut savoir pourquoi on l'a choisi : processeur généraliste, DSP, ASIP ou matériel dédié ? Tout est un compromis entre flexibilité et performance.

§ 0.1Deux approches pour un traitement

Approche logicielleCh0 · s.4–7

Matériel standard : un processeur à jeu d'instructions (GPP, DSP, ASIP). On écrit un programme (C, C++, ASM) compilé en binaire.

Unité de traitement = unité de contrôle (séquence de contrôle qui dépend des instructions) + chemin de données (UAL, registres).

Matériel dédié (SPP)Ch0 · s.4–6

SPP (Single Purpose Processor) : un circuit conçu pour un seul algorithme. Algorithme → machine à états → tables de vérité/transitions → VHDL / Verilog.

SPP = DataPath + contrôle avec une séquence de contrôle prédéfinie (pas d'instructions en mémoire).

§ 0.2Von Neumann vs Harvard

Von Neumanns.8

Instructions et données passent par le même bus de données. Une seule mémoire vue par le CPU.

Harvards.9

Instructions et données passent par deux bus différents : on peut lire une instruction et une donnée en même temps. (Cortex-M3 : architecture Harvard.)

Où sont code et données

En général : Flash = code + constantes ; RAM = variables.

§ 0.3Critères de choix

1 · Coût finalFC = NRE / Q + UC — NRE = coût d'ingénierie non récurrent (conception, une seule fois), Q = quantité produite, UC = coût unitaire. Un ASIC a un NRE énorme mais un UC faible : rentable seulement en grande série.
2 · Time to marketUn retard D sur une fenêtre de vente de durée 2P fait baisser le pic de revenus : pic retardé ≈ R·(P − D)/P. Le retard coûte cher.
3 · PerformanceMIPS/MHz (ou MFLOPS/MHz) ; performance absolue = fréquence × MIPS/MHz ; bande passante mémoire (octets/s). Cortex-M0 0,9 · M3/M4 1,25 · A5 1,57 · A7 1,9 MIPS/MHz.
4 · ÉnergiePuissance en W, énergie en J = P × t → autonomie batterie, dissipation (taille, poids). PC : dizaines de W ; smartphone : W ; MCU : µW → mW.
5 · FlexibilitéÀ quel point il est difficile de faire évoluer ou changer complètement le comportement du système.

MAC (Multiply ACcumulate) : ACC ← ACC + (Ri·Rj + Rk·Rl) en une instruction. Plusieurs UAL commandées par le même signal de contrôle = architecture SIMD. SIMD + MAC = ce qu'on trouve dans les DSP.

§ 0.5Le spectre GPP → ASIC

GPPGeneral Purpose Processor : flexible, moins performant/efficace.
DSPDigital Signal Processor : SIMD + MAC pour le traitement du signal.
ASIPApplication Specific Instruction Processor : cœur (UAL) profondément spécialisé, jeu d'instructions taillé pour une application.
SPP sur FPGAMatériel dédié sur blocs logiques programmables (architecture reprogrammable).
ASICApplication Specific Integrated Circuit : SPP gravé en transistors (architecture fixe). Le plus performant, le moins flexible.

§ 0.6Taxonomie de Flynn

SISD
Single Instr. Single Data

Une UAL, une donnée à la fois. Ex. Cortex-M3.

SIMD
Single Instr. Multiple Data

Plusieurs UAL font la même instruction sur des données différentes. Ex. Cortex-M4, DSP.

MISD
Multiple Instr. Single Data

Plusieurs instructions sur la même donnée (rare).

MIMD
Multiple Instr. Multiple Data

Plusieurs unités indépendantes (multicœurs).

Les slides 31 légendent MISD et MIMD avec « Single Instruction Single/Multiple Data » (copier-coller). Retiens les vrais sens : MISD = Multiple Instruction Single Data, MIMD = Multiple Instruction Multiple Data.

§ 0.7SoC vs microcontrôleur

MCUs.40–41

Un petit ordinateur sur une puce : un ou plusieurs CPU + mémoires (Flash, RAM) + périphériques programmables (GPIO, timers, USART, ADC/DAC…). Usage général : IoT, domotique, électroménager, automobile.

SoCs.37–41

Tout un système sur une puce, conçu pour un domaine (smartphone, décodeur satellite) : GPP + DSP + ASIP + SPP/FPGA, et beaucoup de périphériques avancés. Choix des composants guidé par l'application.

Dilemme smartphone

Il faut à la fois de la flexibilité (mises à jour, apps : GPP) et de la performance (déchiffrement, décodage son/image, 4G : DSP, ASIP, SPP). Solution : un SoC qui contient les deux (ex. Snapdragon, STi5518).

Le cœur du chapitre le plus calculatoire : relier un processeur à des mémoires et à des périphériques, ligne d'adresse par ligne d'adresse. Toutes les questions se résolvent avec quatre formules.

§ 1.1Les trois bus

Bus de contrôle/RD (lecture, actif à 0) · /WR (écriture, actif à 0) · Byte Select (nombre d'octets à transférer).
Bus d'adresseN lignes A₀…A_{N−1}.
Bus de donnéesM lignes D₀…D_{M−1} = taille du mot (8, 16, 32, 64). Processeur 32 bits : mot = 32, demi-mot = 16, double mot = 64.
Capacité d'adressageCh1 · s.5–7
capacité = 2ᴺ octets    espace d'adressage = 0 … 2ᴺ − 1

Chaque octet a son adresse unique. 1 Ko = 2¹⁰, 1 Mo = 2²⁰, 1 Go = 2³⁰. Ex. N = 30 → 2³⁰ = 1 073 741 824 octets = 1 Go.

Avec M = 16 (resp. 32), on récupère 2 (resp. 4) octets dans le même cycle.

Accès aligné / non alignés.11

Sans support non aligné

Une donnée doit être entièrement dans la même ligne mémoire → accès en 1 cycle, mais espace perdu (trous).

Avec support non aligné

Une donnée peut être coupée sur deux lignes → mémoire compacte, mais 2 cycles pour les données coupées.

§ 1.2La mémoire

Profondeur, largeur, tailleCh1 · s.12–13

n lignes d'adresse → 2ⁿ emplacements (profondeur) ; m lignes de données → largeur d'un emplacement.

Taille = 2ⁿ × m bits = 2ⁿ × (m / 8) octets

Ex. n = 10, m = 16 → 1024 × 2 = 2048 octets. L'adresse d'un octet dans la mémoire est un offset ; son adresse effective dépend de où la mémoire est placée dans l'espace du processeur.

Chip Enable /CECh1 · s.14–16
  • /CE = 0 : la puce est connectée au bus de données.
  • /CE = 1 : sorties en haute impédance (tristate) = électriquement déconnectée.
  • Si deux puces pilotent la même ligne (une à 0 V, l'autre à 3,3 V) : court-circuit.
  • Règle : à un instant donné, une seule puce active (0), toutes les autres à 1.

§ 1.3Connecter une mémoire de même largeur

§ 1.4Le compilateur et la mémoire

Listing mémoireCh1 · s.24–26

Pour chaque variable globale, le compilateur réserve une adresse et un type, puis remplace chaque = par la bonne instruction de transfert :

Cycles lecture / écritures.50–54

Lecture (LDR Rn,[Rm]) : le CPU active /CE et /RD, met l'adresse sur le bus d'adresse, la mémoire place le contenu sur le bus de données. Écriture (STR Rn,[Rm]) : le CPU active /CE et /WR, met l'adresse et la donnée sur les bus.

§ 1.5Largeurs ou profondeurs différentes

Largeur m < M → en parallèles.28–36

Il faut M / m mémoires côte à côte, toutes avec le même /CE et les mêmes lignes d'adresse ; chacune prend une tranche du bus de données.

Ex. N = 12, M = 32, m = 8, n = 10 : 4 mémoires ; Mem0 ← D₇…D₀, Mem1 ← D₁₅…D₈, Mem2 ← D₂₃…D₁₆, Mem3 ← D₃₁…D₂₄ ; adresse proc. A₁₁…A₂ → A₉…A₀. L'octet d'adresse 6 est dans Mem2.

Profondeur insuffisante → décodages.38–43

Si la mémoire couvre moins que 2ᴺ, les lignes d'adresse en trop (poids fort) servent à générer les /CE : elles choisissent la zone où la mémoire répond.

Ex. N = 12, M = m = 32, n = 9 : mémoire de 2 Ko. A₁₀…A₂ → A₈…A₀ ; A₁₁ choisit la zone : /CE₀ = A₁₁ (0…2047), /CE₁ = ¬A₁₁ (2048…4095).

Les slides 41–43 écrivent /CE = A9 puis /CE₀ = A9, /CE₁ = /A9. Avec N = 12 et A₁₀…A₂ déjà reliés à la mémoire, la ligne libre est A₁₁ (c'est d'ailleurs ce que montre le schéma). Écris A₁₁ et justifie.
Association de mémoiress.44–48
  • 2ⁱ mémoires à n lignes d'adresse → une mémoire à n + i lignes (en profondeur, avec décodage).
  • Une mémoire 32 bits = 2 × 16 bits ou 4 × 8 bits (en largeur).
  • On peut combiner les deux : barrette 4 Go (1G × 32) = 8 puces de 512 Mo.

§ 1.6Interfaces de périphériques

Vu du processeur, un périphérique = des registresCh1 · s.57–61
  • Les interfaces de périphériques sont reliées au CPU par les bus d'adresse/données, exactement comme une mémoire.
  • Pour le CPU, une interface est un ensemble de registres à adresses prédéfinies qu'on lit et écrit : registres de configuration, d'état, d'entrée/sortie, plus une logique (simple : connexions, mux ; complexe : SPP).
  • Certains bits sont reliés aux broches du SoC : bit à 1 ↔ +V (3,3 V / 5 V), bit à 0 ↔ 0 V.
Accès en C par pointeurCh1 · s.63–64 
#define Reg_name ((volatile type_data *) adr)   // pointeur vers le registre
*Reg_name = valeur;      // écriture
variable  = *Reg_name;   // lecture
Trois erreurs des slides à ne pas recopier : (1) le ; à la fin d'un #define (il serait collé dans chaque expression) ; (2) l'oubli de volatile (sans lui, le compilateur peut supprimer des lectures/écritures de registre) ; (3) l'oubli de 0x (« 40021018 » est un nombre décimal).
Exemples 8255 (PC)Ch1 · s.65–79

LEDs sur Port A (0x300) : clignoter → écrire 0xFF puis 0x00 en boucle.

Afficheur 7 segments sur Port C (0x30E), PC7 = a … PC1 = g, PC0 = h : afficher « 3 » = segments a, b, c, d, g →

PC7…PC0 = 1 1 1 1 0 0 1 0 = 0xF2

Boutons sur PC1, PC0 → LEDs PA1, PA0 :

#define PortA ((volatile uint8_t*) 0x300)
#define PortC ((volatile uint8_t*) 0x30E)
uint8_t etat = *PortC & 0x03;      // MASQUER : ne garder que PC1, PC0
switch (etat) {
  case 0x01: *PortA = 0x01; break;   // BP0 → Led0
  case 0x02: *PortA = 0x02; break;   // BP1 → Led1
  default:   *PortA = 0x00;
}

Le cours le souligne : les autres bits de Port C sont aléatoires, il faut masquer avant de comparer. Et le code des slides oublie les break (fallthrough : on finirait toujours dans default).

STM32F1 (Cortex-M3) : chaque périphérique est un bloc de registres à une adresse fixe. Programmer un GPIO, c'est toujours les mêmes 4 étapes et un peu de masquage de bits.

§ 2.1Memory map : adresse de base + offset

PrincipeCh2 · s.2–7

Chaque mémoire ou périphérique occupe une zone précise de l'espace d'adressage : la memory map. L'adresse où commence un périphérique est son adresse de base ; chaque registre a un offset fixe.

Adresse(Reg X, Periph i) = Base(Periph i) + Offset(Reg X)
Bus du STM32F1Ch2 · s.6

Cortex-M3 → Bus Matrix → AHB (72 MHz : RCC, DMA, Ethernet, USB…) → ponts AHB/APB → APB1 (36 MHz : USART2–5, SPI2/3, I2C, TIM2–7…) et APB2 (72 MHz : GPIOA…GPIOG, AFIO, USART1, SPI1, ADC1/2, TIM1/8).

§ 2.2RCC : activer l'horloge d'abord

Règle n°1Ch2 · s.9–11

Au démarrage, tous les périphériques sont désactivés sauf le RCC (Reset & Clock Control), pour réduire la consommation. C'est le RCC qui les active par un bit ENABLE, un par périphérique.

RCC (base 0x4002 1000) : AHBENR (+0x14 → 0x4002 1014), APB2ENR (+0x18 → 0x4002 1018), APB1ENR (+0x1C → 0x4002 101C).

§ 2.3Structure d'un GPIO

Un port GPIOCh2 · s.13–17
  • Jusqu'à 7–10 ports (GPIOA…), 16 broches par port, chaque broche configurable individuellement.
  • Toute communication avec l'extérieur passe obligatoirement par un GPIO (même l'USART, le SPI… via une broche GPIO).
  • Registres : CRL, CRH (configuration), IDR (entrée), ODR (sortie), BSRR, BRR (mise à 1 / à 0 atomique).
registreCRLCRHIDRODRBSRRBRR
offset0x000x040x080x0C0x100x14

Bases : GPIOA 0x4001 0800 · GPIOB 0x4001 0C00 · GPIOC 0x4001 1000 · GPIOD 0x4001 1400.

4 modes par brocheCh2 · s.19–24
Inputla tension sur la broche est lue dans le bit i d'IDR.
Outputla broche prend la tension du bit i d'ODR (imposé par le CPU).
Alternate Functionla broche est reliée directement à un signal d'un périphérique (USART, Ethernet…).
Analogla broche est reliée à l'ADC/DAC.

Configuration électrique : résistances pull-up / pull-down / no pull (entrée), transistors push-pull / open-drain (sortie seulement), vitesse de commutation 2, 10 ou 50 MHz (plus bas = moins de consommation). Au reset : Input Floating.

CRL / CRH : 4 bits par brocheCh2 · s.29–30

16 broches × 4 bits = 64 bits = 2 registres : CRL pour les broches 0–7, CRH pour 8–15. Broche p → bits 4·(p mod 8) à 4·(p mod 8)+3. Le quartet vaut CNF[1:0] MODE[1:0] :

§ 2.4Programmer une broche : 4 étapes

Accès direct aux registresCh2 · s.32
  1. Définir les registres utilisés (taille, adresse) avec des #define pointeurs.
  2. Activer l'horloge du GPIO dans RCC_APB2ENR.
  3. Configurer la broche : effacer son quartet dans CRL/CRH, puis écrire le nouveau.
  4. Écrire (ODR / BSRR / BRR) ou lire (IDR & masque) la valeur.
// LED sur PC9 (sortie push-pull 2 MHz) + bouton sur PA2 (input floating)
#define RCC_APB2ENR ((volatile uint32_t*) 0x40021018)
#define GPIOC_CRH   ((volatile uint32_t*) 0x40011004)
#define GPIOC_BSRR  ((volatile uint32_t*) 0x40011010)
#define GPIOC_BRR   ((volatile uint32_t*) 0x40011014)
#define GPIOA_CRL   ((volatile uint32_t*) 0x40010800)
#define GPIOA_IDR   ((volatile uint32_t*) 0x40010808)   // base + 0x08

*RCC_APB2ENR |= 0x14;                 // GPIOA (bit 2) + GPIOC (bit 4)
*GPIOC_CRH &= ~(0xFu << 4);           // PC9 → quartet bits 7..4 de CRH
*GPIOC_CRH |=  (0x2u << 4);           // 0010 = output PP 2 MHz
*GPIOA_CRL &= ~(0xFu << 8);           // PA2 → bits 11..8 de CRL
*GPIOA_CRL |=  (0x4u << 8);           // 0100 = input floating
while (1) {
  if (*GPIOA_IDR & (1u << 2))  *GPIOC_BSRR = 1u << 9;   // appuyé → LED ON
  else                           *GPIOC_BRR  = 1u << 9;   // sinon LED OFF
}
Le slide 44 donne GPIOA_IDR = 0x40010800 (même adresse que CRL) : c'est faux, IDR = base + 0x08 = 0x40010808. Le slide 47 annonce « Pin 0 » alors que le code configure la broche 2 (décalage de 8).

§ 2.5Masquage logique & BSRR / BRR

Les 4 opérations de base
Mettre le bit k à 1REG |= (1u << k);
Mettre le bit k à 0REG &= ~(1u << k);
Inverser le bit kREG ^= (1u << k);
Tester le bit kif (REG & (1u << k)) …
Écrire un champ de w bits à la position pREG = (REG & ~(((1u<<w)−1) << p)) | (val << p);
Inconvénient du masquages.39

Chaque |= ou &= = 3 instructions : lire le registre, opération logique, réécrire. Code plus long, plus lent, et non atomique (une interruption entre la lecture et l'écriture peut écraser une modification).

Masquage câblé : BSRR / BRRs.40–42

BSRR (Bit Set) : un 1 au bit i → ODRᵢ = 1 ; un 0 → ODRᵢ inchangé.
BRR (Bit Reset) : un 1 au bit i → ODRᵢ = 0 ; un 0 → inchangé.
1 seule instruction (écriture simple =), valable seulement pour ODR.

§ 3.1Pourquoi une couche d'abstraction

  

    Problème de l'accès directCh3 · s.2–3
    
Il faut connaître (1) les adresses des registres, (2) la structure des registres et les valeurs des paramètres, (3) faire les décalages et masquages. Approche compliquée, documentation technique nécessaire, temps de développement long.

  

  

    Firmware / HAL / driverCh3 · s.4–5
    
Programme utilisateur → Firmware HAL (Hardware Abstraction Layer, drivers ST FWL) → Matériel STM32. Le constructeur fournit ces librairies pour exploiter les périphériques en faisant abstraction des adresses et des registres.

    
Le firmware est du code (C ou ASM) qui dépend complètement de la plateforme : il n'est pas portable sur un autre matériel. « Firm » = ferme, entre Hard et Soft.

  


  
§ 3.2Les 3 étapes d'abstraction

  

    
1 · Adresses → structuresstm32f10x.h déclare une struct par type de périphérique dont les champs ont les mêmes offsets que les registres, et un pointeur par instance : GPIOC->CRH, RCC->APB2ENR. Le compilateur remplace l'accès au champ par base + offset.

    
2 · Valeurs → constantesstm32f10x_gpio.h nomme les paramètres : GPIO_Mode_Out_PP, GPIO_Speed_2MHz, GPIO_Pin_9 = 1<<9.

    
3 · Décalages → fonctionsstm32f10x_gpio.c : GPIO_Init, GPIO_SetBits (écrit BSRR), GPIO_ResetBits (écrit BRR), GPIO_ReadInputDataBit…

Une interruption, c'est trois phases : sauvegarder, servir, restaurer. Le Cortex-M3 rend les deux phases de bord automatiques et sait les sauter quand elles sont inutiles. C'est l'exercice de chronogramme du DS.

§ 4.2Déroulement d'une interruption

  

    PUSH → Handler → POP
    
    
      
  1. PUSH (12 cycles) : sauvegarde automatique (matérielle) de R0–R3, R12, LR (R14), PC (R15), PSR dans la pile, en parallèle avec la lecture de l'adresse du handler (architecture Harvard).
    2. 
      
  2. Handler (ISR) : la fonction C associée.
    3. 
      
  3. POP (12 cycles) : restauration des registres.
    4. 
    

    
Le CM3 peut aussi interrompre les instructions multi-cycles (load/store multiples) → meilleure latence.

  


  
§ 4.3Les 4 optimisations du Cortex-M3

  

    

      Tail chaining (TC) · 6 cycles
      
Une IRQ i arrive pendant le handler d'une IRQ j plus prioritaire : i attend. À la fin de j, au lieu de POP + PUSH (24 cycles inutiles : on restaure puis resauvegarde la même chose), le CM3 fait un TC de 6 cycles (juste lire l'adresse du handler i).

    

    

      Préemption du POP · 1–12 + 6
      
L'IRQ arrive pendant le POP : le POP est arrêté immédiatement (il ne fait que relire la pile, aucune perte), puis TC 6 cycles. Coût total 7 à 18 cycles. Indépendant des priorités relatives des deux IRQ.

    

    

      Imbrication (nested)
      
Une IRQ plus prioritaire arrive pendant un handler : le handler est suspendu, PUSH 12, on sert la prioritaire, POP 12, et on reprend le handler suspendu là où il était.

    

    

      Late arrival
      
Une IRQ plus prioritaire arrive pendant le PUSH d'une autre : un seul PUSH suffit. À la fin du PUSH, le CM3 sert directement la plus prioritaire, puis enchaîne l'autre par TC.

    

  

  
Pour l'ARM7 / x86 : chaque handler a son propre PUSH et POP complets (pas de TC, pas de late arrival). Question de cours classique : comparer les deux enchaînements et donner le gain (24 → 6 cycles).

§ 5.1Conditions de déclenchement

  

    Deux autorisations
    
    
      
  1. Au niveau du périphérique : autoriser l'envoi d'IRQ suite à un événement (réception série, fin de conversion…). L'événement met un bit d'état (FLAG) à 1.
    2. 
      
  2. Au niveau du NVIC : autoriser l'entrée (bit Enable) et lui donner une priorité. Le FLAG met le pending bit du NVIC à 1.
    3. 
    

  

  

    
ISERxInterrupt Set-Enable : écrire 1 au bit i autorise l'IRQ i.

    
ICERxInterrupt Clear-Enable : écrire 1 interdit l'IRQ i.

    
ISPRxSet-Pending : met l'IRQ en attente (normalement fait par le périphérique).

    
ICPRxClear-Pending : retire l'attente (fait automatiquement par le matériel quand le handler démarre).

  

  
STM32F1 : 68 IRQ → 3 registres de 32 bits par fonction (0–31, 32–63, 64–67).


  
§ 5.2Priorités : groupe et sous-priorité

  

    Preemption priority vs SubPriority
    
ARM range les IRQ en groupes (preemption priority) et donne à chacune un rang dans son groupe (subpriority). Valeur plus petite = plus prioritaire.

    
    
      
  • Deux IRQ en attente : on sert d'abord la plus prioritaire (groupe, puis sous-priorité).
    • 
      
  • Une IRQ en cours n'est préemptée que par une IRQ d'un groupe strictement plus prioritaire. La sous-priorité ne sert jamais à préempter, seulement à départager les attentes.
    •

§ 5.4Les handlers

  

    Nommer la fonction suffit
    
Le startup file (fourni par ARM/ST) remplit la table des vecteurs avec des noms fixes. Il suffit d'écrire une fonction avec le bon nom : void EXTI0_IRQHandler(void), SysTick_Handler, USART1_IRQHandler… Le linker met son adresse au bon vecteur.

  

  

    Effacer le FLAG dans le handler
    
Quand le handler démarre, le pending bit du NVIC est effacé automatiquement, mais le FLAG du périphérique reste à 1 → l'IRQ se redéclencherait sans nouvel événement. Il faut l'effacer dans le handler : PPP_ClearITPendingBit(…) (malgré son nom, elle efface le FLAG du périphérique).

  

  

    Interruption globale / groupée
    
Plusieurs FLAGs reliés par un OU logique à une seule entrée NVIC (nombre d'entrées limité). Dans le handler, tester chaque source :

    
void EXTI9_5_IRQHandler(void) {
  if (EXTI_GetITStatus(EXTI_Line7)) { /* … */ EXTI_ClearITPendingBit(EXTI_Line7); }
  if (EXTI_GetITStatus(EXTI_Line8)) { /* … */ EXTI_ClearITPendingBit(EXTI_Line8); }
}

  


  
§ 5.5Le bloc EXTI

  

    EXTernal Interrupt/event controller
    
    
      
  • 20 lignes : EXTI0…15 viennent des GPIO (via AFIO, GPIOA par défaut), EXTI16 = PVD, 17 = RTC, 18 = USB, 19 = Ethernet.
    • 
      
  • La ligne EXTIi est reliée à la broche i d'un seul port : PA3, PB3, PC3… partagent EXTI3, on choisit le port avec GPIO_EXTILineConfig(GPIO_PortSourceGPIOx, GPIO_PinSourcei).
    • 
      
  • Chaque ligne peut générer une interruption (vers le NVIC) ou un événement (impulsion sur une broche AF, choisie par AFIO_EVCR).
    • 
    

  

  

    
RTSRRising Trigger : 1 = déclenche sur front montant.

    
FTSRFalling Trigger : 1 = déclenche sur front descendant (les deux peuvent être actifs).

    
SWIERSoftware Interrupt Event : simule une activité sur la ligne.

    
IMRInterrupt Mask : 1 = interruption autorisée, 0 = masquée.

    
EMREvent Mask : 1 = génération d'événement autorisée.

    
PRPending : mis à 1 quand le front arrive ; à effacer dans le handler (sinon re-déclenchement).

Ch0question de cours

    
Comment justifier le choix GPP / DSP / ASIP / FPGA / ASIC pour une application ?

    
    
      
  1. Lister les besoins : performance (débit, temps réel), énergie (batterie ?), flexibilité (mises à jour ?), quantité produite, time to market.
    2. 
      
  2. Placer chaque besoin sur l'axe flexibilité ↔ performance (GPP … ASIC).
    3. 
      
  3. Coût : FC = NRE/Q + UC ; ASIC seulement si Q est très grand.
    4. 
      
  4. Si besoins contradictoires (smartphone) → SoC qui combine GPP + accélérateurs.
    5. 
    

    
Ne réponds jamais « le plus performant » : la réponse attendue est un compromis argumenté critère par critère.

  


  

    
Ch0 · s.15–27

    
Comment comparer le coût d'un calcul sur GPP, DSP (SIMD + MAC) et matériel dédié ?

    
    
      
  1. Écrire la séquence d'instructions sur le GPP (chargements, produits, additions, transferts) et la compter par type.
    2. 
      
  2. Refaire avec 2 UAL + MAC : les produits se font par paires, l'accumulation dans ACC.
    3. 
      
  3. Matériel dédié : 0 instruction, tout en parallèle (1 cycle par étage).
    4. 
      
  4. Conclure sur cycles (performance) et nombre d'opérations (énergie), puis flexibilité.
    5. 
    

    
Les chiffres de référence pour 4 termes : 22 instructions (GPP) → 10 (SIMD + MAC) → 0 (SPP).

  


  

    
Ch1 · s.5–13

    
Comment calculer la capacité d'adressage, la taille d'une mémoire et le nombre de lignes d'adresse ?

    
    
      
  1. Capacité processeur = 2ᴺ octets ; espace = 0 … 2ᴺ − 1.
    2. 
      
  2. Taille mémoire = 2ⁿ × m/8 octets.
    3. 
      
  3. Pour couvrir tout l'espace avec une mémoire de largeur m = M : 2ᴺ = 2ⁿ × M/8 ⇒ n = N − log₂(M/8) (M = 8 → n = N ; 16 → N−1 ; 32 → N−2).
    4. 
      
  4. Convertir avec 1 Ko = 2¹⁰, 1 Mo = 2²⁰, 1 Go = 2³⁰.
    5. 
    

    
Toujours raisonner en octets côté processeur : c'est ce que compte l'adresse.

  


  

    
Ch1 · s.17–23

    
Comment câbler une mémoire de même largeur que le processeur ?

    
    
      
  1. Vérifier M = m.
    2. 
      
  2. Calculer k = log₂(M/8) : les k lignes de poids faible (A₀ ou A₁A₀) ne vont pas à la mémoire, elles servent avec Byte Select à choisir les octets.
    3. 
      
  3. Relier A_{k} … A_{k+n−1} du processeur à A₀ … A_{n−1} de la mémoire.
    4. 
      
  4. Relier les M lignes de données une à une.
    5. 
      
  5. Si les lignes d'adresse sont toutes utilisées : /CE = 0 en permanence (mémoire unique).
    6. 
    

    
Dessine toujours le schéma avec les numéros des lignes aux deux bouts : c'est là que sont les points.

  


  

    
Ch1 · s.28–36

    
Comment utiliser des mémoires moins larges que le bus de données (m < M) ?

    
    
      
  1. Nombre de puces côte à côte = M / m.
    2. 
      
  2. Toutes reçoivent les mêmes lignes d'adresse (A_k … A_{k+n−1}, k = log₂(M/8)) et le même /CE.
    3. 
      
  3. La puce j reçoit la tranche de données D_{(j+1)m−1} … D_{jm}.
    4. 
      
  4. Pour savoir où est un octet d'adresse a : la puce est donnée par (a mod (M/8)) / (m/8), la ligne par a div (M/8).
    5. 
    

    
Corrigé — N = 12, M = 32, n = 10, m = 8

      
4 puces (Mem0…Mem3), toutes sur A₁₁…A₂ → A₉…A₀ et /CE = 0. Mem0 ← D₇…D₀, Mem1 ← D₁₅…D₈, Mem2 ← D₂₃…D₁₆, Mem3 ← D₃₁…D₂₄.

      
Octet 6 : 6 mod 4 = 2 → Mem2, ligne 6 div 4 = 1. Octet 7 → Mem3 ligne 1.

    

  


  

    
Ch1 · s.38–46

    
Comment placer une (ou plusieurs) mémoire(s) plus petite(s) dans l'espace d'adressage ?

    
    
      
  1. Relier d'abord les lignes « internes » : A_k … A_{k+n−1} → mémoire.
    2. 
      
  2. Les lignes restantes A_{k+n} … A_{N−1} forment le numéro de zone (2^(N−k−n) zones possibles).
    3. 
      
  3. Pour qu'une mémoire réponde dans la zone z, /CE doit valoir 0 exactement quand ces lignes valent z (/CE actif bas → expression inversée).
    4. 
      
  4. Donner la plage : zone z couvre z × taille … (z+1) × taille − 1.
    5. 
      
  5. Vérifier qu'à chaque adresse, une seule /CE est à 0.
    6. 
    

    
Avec une seule ligne libre A : /CE₀ = A (zone basse) et /CE₁ = ¬A (zone haute). Avec deux lignes, il faut un décodeur 2 vers 4 (ou les équations /CEᵢ en somme de produits).

    
Corrigé — N = 12, M = m = 32, n = 9 (cours s.38–43)

      
k = 2, la mémoire prend A₁₀…A₂. Ligne libre : A₁₁. Taille mémoire = 2⁹ × 4 = 2048 o.

      
Mem0 en 0…2047 : /CE₀ = A₁₁ ; Mem1 en 2048…4095 : /CE₁ = ¬A₁₁. Ensemble : tout l'espace est rempli.

    

  


  

    
Ch1 · s.24–26

    
Comment construire le listing mémoire des variables et traduire les affectations en LDR/STR ?

    
    
      
  1. Partir de l'adresse de début de la RAM et placer chaque variable dans l'ordre de déclaration.
    2. 
      
  2. Aligner : une variable de 2 octets commence à une adresse paire, de 4 octets à un multiple de 4 (sauf si non aligné supporté).
    3. 
      
  3. Lecture : LDRB/LDRSB (8 bits), LDRH/LDRSH (16), LDR (32). Écriture : STRB, STRH, STR.
    4. 
      
  4. Chaque instruction implique une valeur de Byte Select (00, 01, 10) et une valeur de A₁A₀ (offset dans la ligne).
    5. 
    

    
Le « S » de LDRSB/LDRSH = signé : extension du bit de signe vers 32 bits.

  


  

    
Ch1 · s.63–79

    
Comment piloter un port d'E/S en C (LEDs, 7 segments, boutons) ?

Ch2 · s.36–41DS 2021 Pb Q3

    
Comment modifier un champ de bits sans toucher aux autres ?

    
    
      
  1. Repérer la position p et la largeur w du champ.
    2. 
      
  2. Construire le masque ((1u << w) − 1) << p (ex. 2 bits en position 4 : 0x3 << 4 = 0x30).
    3. 
      
  3. Effacer : REG &= ~masque;
    4. 
      
  4. Écrire : REG |= (valeur << p);
    5. 
      
  5. Plusieurs champs d'un coup : additionner (OU) les masques et les valeurs.
    6. 
    

    
Ne fais jamais seulement |= sur un champ de plusieurs bits : s'il contenait déjà des 1, le résultat est faux. Toujours effacer puis écrire.

  


  

    
Ch2 · s.32–50

    
Comment configurer et utiliser une broche GPIO du STM32F1 par accès registres ?

    2. 
      
  2. Horloge : *RCC_APB2ENR |= 1 << (2 + n°port) (A = 2, B = 3, C = 4…).
    3. 
      
  3. Registre : CRL si broche < 8, CRH sinon ; décalage 4 × (p mod 8).
    4. 
      
  4. Quartet : output PP 2 MHz = 0x2, input floating = 0x4, etc. Effacer puis écrire.
    5. 
      
  5. Utiliser : BSRR = 1<<p (1), BRR = 1<<p (0), IDR & (1<<p) (lire).
    6. 
    

    
Vérifie ton calcul avec le configurateur du § 2.5 : il affiche le registre, le décalage et le code.

  LcdCtrlx->PalReg  = (LcdCtrlx->PalReg  & ~mask) | pal;
}

      
Le corrigé officiel écrit if (Id & (1<<i) != 0) : en C, != est prioritaire sur &, ce qui donne Id & 1. Il faut les parenthèses.

Comment déclencher un handler sur un front d'une broche (EXTI) ?

    
    
      
  1. Horloges : GPIOx + AFIO (APB2).
    2. 
      
  2. GPIO : broche en entrée (floating / pull).
    3. 
      
  3. AFIO : GPIO_EXTILineConfig(GPIO_PortSourceGPIOx, GPIO_PinSourcei) relie la ligne EXTIi à la broche i du port x.
    4. 
      
  4. EXTI : ligne(s), mode Interrupt, front (Rising / Falling / Rising_Falling), ENABLE, EXTI_Init.
    5. 
      
  5. NVIC : bon IRQn (EXTI0…4 seuls, 5–9 → EXTI9_5, 10–15 → EXTI15_10), priorités, ENABLE.
    6. 
      
  6. Handler au bon nom ; tester EXTI_GetITStatus si groupé ; EXTI_ClearITPendingBit.
    7. 
    

    
Deux broches de même numéro (PA3 et PD3) ne peuvent pas utiliser EXTI en même temps : une seule ligne EXTI3. Dans le DS 2021, PB3 n'a donc aucun effet (EXTI3 est relié à PD3).

  


  

    
Ch4DS 2021 · Ex1 Q3–Q4 (4 pts)

    
Comment tracer le chronogramme de plusieurs interruptions sur Cortex-M3 ?

    
    
      
  1. Lister les IRQ : instant (front + type de front configuré, SysTick tous les N cycles), priorité, durée du handler (somme des cycles).
    2. 
      
  2. Avancer dans le temps. Processeur libre + IRQ → PUSH 12, puis on sert la plus prioritaire en attente à la fin du PUSH (late arrival).
    3. 
      
  3. IRQ plus prioritaire pendant un handler → handler suspendu, PUSH 12, imbrication.
    4. 
      
  4. Fin d'un handler : une IRQ éligible attend → TC 6 ; sinon POP 12 (vers le handler suspendu ou le programme).
    5. 
      
  5. IRQ éligible pendant un POP → POP arrêté + TC 6.
    6. 
      
  6. Remplir le tableau : début et fin de chaque exécution de handler (le temps où il est suspendu compte dans l'intervalle).
    7. 
    

    
Un handler qui ne remet pas son FLAG à 0 (ou le remet trop tôt alors que la ligne bouge encore) se ré-exécute. Lis bien où est placé le ClearPendingBit.

Comment décider qui préempte qui avec PRIGROUP, groupe et sous-priorité ?

    
    
      
  1. Lire PRIGROUP → nombre de bits de groupe g et de sous-priorité 4 − g.
    2. 
      
  2. Découper la valeur de priorité (4 bits) : bits forts = groupe, bits faibles = sous-priorité.
    3. 
      
  3. Préemption : seulement si groupe strictement plus petit.
    4. 
      
  4. Choix entre IRQ en attente : groupe, puis sous-priorité, puis numéro d'IRQ (le plus petit gagne).
    5. 
    

    
Exception figée : Reset (−3), NMI (−2), HardFault (−1) passent avant tout ce que tu peux configurer.

S · 2Les ponts

  

    
I → II
Un GPIO est une interface de périphérique du Ch1 : des registres à une adresse, câblés aux broches. Le 8255 et le STM32 se programment pareil : *(volatile T*)adr.

    
II → III
La FWL ne fait que remplacer adresses, valeurs et décalages par des structures, constantes et fonctions. Le DS te demande de refaire cette couche pour un périphérique inventé.

    
0 → IV
L'architecture Harvard du CM3 permet de lire le vecteur pendant la sauvegarde des registres : d'où le PUSH en 12 cycles.

    
II/III → V
Une IRQ EXTI traverse GPIO → AFIO → EXTI → NVIC. Chaque bloc a son horloge, sa config et son bit à effacer.
